# SalesCentral (Android SDK)

Kotlin SDK for the **SalesCentral** backend — the Android counterpart of the
[Swift SDK](../swift/README.md), with the **same public surface**: users,
purchases, subscriptions, credits, retention rewards, sessions, custom
events, paywalls, remote config, and experiments, behind a single
`SalesClient` + a `SalesCentral` facade.

Each app gets its own set of 10 unguessable URLs (generated by the admin);
the SDK composes calls from those. No third-party dependencies beyond
Google/Jetpack ones (`billing-ktx`, `kotlinx-coroutines`,
`lifecycle-process`); JSON is `org.json`, HTTP is `HttpsURLConnection`.

## Backend setup — read this first

Full Android support (production identities, validated Play purchases,
FCM push) requires the app's **Google Play credentials on the server**:
admin → App Detail → Settings → **Google Play (Android)** card. Paste the
Android package name and a GCP **service-account key JSON** granted:

1. **Play Console API access** (Play Console → Users and permissions) —
   validates purchases via the Play Developer API,
2. **Play Integrity API** (enabled on the same Google Cloud project) —
   device attestation,
3. **Firebase Cloud Messaging API** — push (the key's `project_id`
   selects the Firebase project).

Then regenerate `SalesCentral.json` from the SDK config card — it will
include `"playIntegrity": true`, which switches the SDK to
[PlayIntegrityAttestService](salescentral/src/main/java/com/salescentral/sdk/DeviceAttest.kt).

**Without** that server config, an Android app still works but runs as a
**sandbox identity** (like the iOS Simulator): play-money credits,
excluded from production analytics, and Play purchases are rejected —
the SDK leaves rejected purchases unacknowledged, so Google auto-refunds
them after 3 days and no money is silently kept.

For **subscriptions**, also connect Real-Time Developer Notifications:
create a Cloud Pub/Sub topic, point Play Console → Monetization setup →
RTDN at it, and add a push subscription targeting the app's
**"Google Play RTDN"** URL (shown on the admin App Detail page). Renewals,
cancellations, revocations and refunds then arrive server-side like
Apple's webhook. The server also lazily re-validates any Play subscription
that looks expired, so a missed notification self-heals on the next
app foreground.

Optional, recommended at scale: enable "Manage and download my response
encryption keys" in Play Console → App integrity and paste the two keys
into the same admin card — integrity tokens are then verified locally
(no decodeIntegrityToken API quota). Free trials and actual paid prices
are resolved via the Play `orders` API automatically.

Design details: `docs/superpowers/specs/2026-07-09-google-play-backend-design.md`.

## Install

The SDK is an Android library module (`com.salescentral.sdk`, minSdk 26, compileSdk 37).
Since 1.1.0 it is built with AGP 9 (built-in Kotlin) and Play Billing Library 9, so a
consuming app needs **AGP 9.1+ and compileSdk 37+** (AGP 9 enforces the same-or-higher
compileSdk rule for library consumers by default).

**Option A — JitPack** (from the public mirror, recommended):

```kotlin
// settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        google(); mavenCentral()
        maven("https://jitpack.io")
    }
}

// app/build.gradle.kts
dependencies {
    implementation("com.github.Feghal:SalesCentral-Android:1.1.0")
}
```

**Option B — include the module** (monorepo / vendored):

```kotlin
// settings.gradle.kts
include(":salescentral")
project(":salescentral").projectDir = file("path/to/sdk/android/salescentral")

// app/build.gradle.kts
dependencies { implementation(project(":salescentral")) }
```

**Option C — publish an AAR** from this project (`./gradlew :salescentral:assembleRelease`,
artifact in `salescentral/build/outputs/aar/`) into your Maven repository.

## Configure

Drop a **`SalesCentral.json`** file into your app's `src/main/assets/`
folder — same fields as the iOS `SalesCentral.plist`. Generate it from the
admin's App Detail → SDK config card:

```json
{
  "baseURL": "https://sales-central.org",
  "apiKey": "csk_XXXXXXXXXXXXXXXXXXXXXXXXXXXX",
  "tokens": {
    "createOrFetchUser": "YYYYYYYYYYYY",
    "restoreUser": "YYYYYYYYYYYY",
    "applyPurchases": "YYYYYYYYYYYY",
    "currentSubscription": "YYYYYYYYYYYY",
    "spendCredits": "YYYYYYYYYYYY",
    "claimReward": "YYYYYYYYYYYY",
    "recordSession": "YYYYYYYYYYYY",
    "recordEvent": "YYYYYYYYYYYY",
    "attestChallenge": "YYYYYYYYYYYY",
    "attestKey": "YYYYYYYYYYYY"
  }
}
```

## Quick start

One call from your `Application`:

```kotlin
import com.salescentral.sdk.SalesCentral

class MyApp : Application() {
    override fun onCreate() {
        super.onCreate()
        MainScope().launch { SalesCentral.start(this@MyApp) }
    }
}
```

`start()` reads `assets/SalesCentral.json`, ensures a guest user, starts
the Play purchase observer, and starts the session tracker. Idempotent. If
the first launch is offline, the SDK watches for reconnection and retries
by itself.

Observe state from Compose (or any coroutine scope):

```kotlin
@Composable
fun StatusView() {
    val store = SalesCentral.store
    val user by store.user.collectAsState()
    Column {
        Text("Tier: ${store.tier}")
        Text("Credits: ${store.creditBalance}")
        if (store.isInTrial) Text("Free trial active")
        Button(onClick = { scope.launch { store.restorePurchases() } }) {
            Text("Restore Purchases")
        }
    }
}
```

`store.isPaid` / `store.tier` / `store.isInTrial` are **expiry-aware** —
they respect `expiresAt` / `trialEndsAt` locally, so a long-running app
reflects a lapsed subscription with no server round-trip. The store also
re-syncs subscription/premium when the app returns to the foreground;
call `store.refreshSubscription()` to force a re-sync (e.g. before a
paywall).

## Loading + buying products

```kotlin
// 1. Load products for your paywall.
//    No identifiers — the SDK already knows them from the admin.
val products: List<ProductDetails> = SalesCentral.loadProducts()

// 2. Buy a loaded product (needs the Activity for the Play dialog).
suspend fun buy(activity: Activity, product: ProductDetails) {
    try {
        when (val result = SalesCentral.purchase(activity, product)) {
            is PurchaseResult.Success -> showThanks()
            is PurchaseResult.UserCancelled -> {}
            is PurchaseResult.Pending -> showPendingHint()
            is PurchaseResult.Unverified -> showError(result.reason)
            is PurchaseResult.NotEntitled -> showPaywall(result.reason) // nothing granted
        }
    } catch (e: SalesError) {
        showError(e.message)
    }
}

// Or skip the load step entirely:
SalesCentral.purchase(activity, productId = "com.foo.pro.monthly")
```

`purchase()` drives the Play dialog, uploads the receipt, applies effects,
**acknowledges the purchase only after the server accepts it** (Google
auto-refunds unacknowledged purchases — the safety analog of iOS finishing
a transaction only after upload), and refreshes the shared store. You never
touch `BillingClient` yourself. Consumables (admin type `consumable`) are
consumed instead of acknowledged so they can be repurchased.

**Read what a product grants** — for paywall benefit rows, without
hard-coding them:

```kotlin
for (effect in SalesCentral.store.effects(product.productId)) {
    when (effect) {
        is ProductEffect.GrantCredits -> addRow("${effect.amount} credits")
        is ProductEffect.SetPremium -> addRow("${effect.tier ?: "Pro"} access")
        is ProductEffect.GrantEntitlement -> addRow("Unlocks ${effect.entitlement}")
        is ProductEffect.UnlockFeature -> addRow("Unlocks ${effect.feature}")
        is ProductEffect.Unknown -> {} // newer effect type
    }
}
```

## Calling from anywhere

`SalesCentral.shared` is the underlying `SalesClient` — use it for all the
lower-level operations:

```kotlin
SalesCentral.shared.spendCredits(50, reason = "image_gen")
SalesCentral.shared.recordSession(start = openedAt, end = Instant.now())
SalesCentral.shared.setUserProperties(mapOf(
    "email" to SalesPropertyValue.of("alice@example.com"),
    "lifetime_orders" to SalesPropertyValue.of(3),
))
SalesCentral.shared.track("level_completed", mapOf("score" to 8420))

// Server-defined paywall + remote-config (variants applied automatically)
val paywall = SalesCentral.shared.paywall(key = "main_paywall")
val products = paywall.loadProducts()   // List<ProductDetails> in admin order
val label = SalesCentral.shared.remoteConfig("cta_label", "Continue")
```

### Charge credits

**On-device work** — gate locally on the cached balance, do the work, then
charge on success with an idempotency key (a timed-out retry with the same
key never double-debits):

```kotlin
if (SalesCentral.store.creditBalance < 50) return showPaywall()
val intentKey = UUID.randomUUID().toString()
val result = runLocalRender()
SalesCentral.shared.spendCredits(50, reason = "render", idempotencyKey = intentKey)
```

**Server-delivered work** — charge FIRST, then send the returned
`credits.receipt` (a signed, 10-minute proof of the debit) to your backend
with the work request. Your backend verifies it offline with the receipt
signing secret from the admin panel (never ship that secret in the app) and
delivers only against a valid, unconsumed receipt. See the Swift README's
"Charge credits" section — the wire format is identical.

```kotlin
val intentKey = UUID.randomUUID().toString()
val credits = SalesCentral.shared.spendCredits(50, reason = "image_gen", idempotencyKey = intentKey)
val receipt = credits.receipt ?: throw PaywallError.MissingReceipt
val image = myBackend.generate(prompt = prompt, receipt = receipt)
```

## Operations

Top-level facade (`SalesCentral.…`):

| API | Purpose |
|---|---|
| `start(context)` | One-shot config + bootstrap. Reads `assets/SalesCentral.json`, ensures the user, wires up observers. |
| `configure(context, config)` | Inject an explicit `SalesConfig` (tests, dynamic setups). First call wins. |
| `loadProducts()` / `loadProduct(id)` / `reloadProducts()` | Play `ProductDetails` for the SKUs the admin registered. No identifiers in app code. |
| `paywall.loadProducts()` | Products for one paywall, filtered + ordered by `paywall.productIds`. |
| `loggingEnabled` | Toggle SDK logging (logcat tag `SalesCentral`; on by default in debuggable builds). |
| `purchase(activity, product)` / `purchase(activity, productId)` | End-to-end purchase: dialog → upload → acknowledge → store refresh. |
| `store` | Shared `SalesStore` with `StateFlow`s for UI. |
| `store.products` / `store.effects(productId)` | Registered catalog as `List<SalesProduct>` with typed `List<ProductEffect>`. |
| `store.refreshSubscription()` | Cheap re-pull of subscription + premium. Auto-fires on app foreground. |
| `shared` | Underlying `SalesClient` for direct API calls. |
| `registerPushToken(token)` / `unregisterPushToken()` | FCM token + notification permission status → backend. |

Underlying client (`SalesCentral.shared.…`) — same table as the
[Swift README](../swift/README.md#operations): `ensureUser(context)`,
`updateContext`, `setUserProperty` / `setUserProperties`, `paywall(key)`,
`remoteConfig(key, fallback)`, `activeExperiments()`, `refreshConfig()`,
`restorePurchases(receipts, context)`, `applyReceipts` / `applyReceipt`,
`configuredProducts` / `effects(productId)`, `currentSubscription()`,
`spendCredits(amount, reason, idempotencyKey)`, `claimReward()`,
`recordSession(start, end, durationSec)`, `track` / `trackBatch`,
`clearUser()`. Semantics (idempotency, 401 handling, cache refresh
cadence, error codes) mirror iOS exactly.

## Push notifications

```kotlin
class MyMessagingService : FirebaseMessagingService() {
    override fun onNewToken(token: String) {
        CoroutineScope(Dispatchers.IO).launch {
            runCatching { SalesCentral.registerPushToken(token) }
        }
    }
}
```

The token and the current notification permission are stored on the user
record. (Sending to FCM is a pending backend feature — see the table at
the top.)

## Error handling

All failures throw `SalesError`; HTTP errors carry the server's
machine-readable code:

```kotlin
try {
    SalesCentral.shared.spendCredits(50, reason = "image_gen")
} catch (e: SalesError.Http) {
    when (e.code) {
        "insufficient_credits" -> showPaywall()
        else -> showAlert(e)
    }
}
```

The error-code table (`insufficient_credits`, `already_claimed`,
`not_eligible`, `rewards_disabled`, `app_key_required`,
`invalid_user_token`, `endpoint_not_found`, `product_not_registered`, …)
is identical to the [Swift README](../swift/README.md#error-handling).

## Token storage

Default store is app-private `SharedPreferences`. Unlike the iOS Keychain
it does **not** survive uninstall — for paying users the authoritative
recovery path is `restorePurchases()` (re-links by Play purchases), the
same way StoreKit entitlements are the authoritative path on iOS. Override
for tests via `SalesConfig(tokenStore = InMemoryTokenStore())` +
`SalesCentral.configure(context, config)`.
